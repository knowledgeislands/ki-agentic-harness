# Bootstrap or rebootstrap the current company

Read the canonical `ki-agent-coordination-paperclip` skill and its existing-estate onboarding guide. Assess the current Paperclip company and its verified Agora home; infer their identities from the run and repository evidence, not from this prompt. Reuse what is already working. Reconcile repository projects, existing work and decisions, agents and responsibilities, skill access, roadmap task links, and recurring obligations without duplicating them. Check whether current employees can cover the work with clearer remits, reassignment or configuration before proposing hires. Keep repository work in its owning project and company coordination in Coordination.

First return a read-only assessment and a one-screen, plain-language decision brief. Put detailed inventories, API evidence, exact diffs, history and future work in linked supporting records, not in the approval text. Ask approval for only the next bounded action: why it matters, who will do it, what it permits, what it does not permit, and what result will come back. Make each question understandable on its own: explain what happened, what has already been checked, why the person's answer is needed, the recommended choice and what happens if they wait. Do not seek repeat approval for unchanged accepted scope or another identical investigation when the real blocker is a missing owner or permission. Hold only the affected change while other authorised work continues. Do not create projects or tasks, move or hire agents, resume held work, change repositories, or activate schedules without the relevant approval. Use audit plus conform dry-run only for daily preflight; follow the guide for the technical checks and evidence.
