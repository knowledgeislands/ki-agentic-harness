# Bootstrap or rebootstrap the current company

Before creating or rebinding a repository project, check whether one already belongs to that repository across the company's active and archived projects. A project list visible only to this agent cannot prove a no-match. If company-wide access is missing, ask an authorised board operator for one targeted, read-only check covering the proposed project changes. Report matches or a verified no-match with observation time, archived coverage and caller-scope evidence. Keep existing approvals; do not ask the principal to reconstruct project data or approve the same scope again. While the check is pending, hold only affected project changes and continue independent read-only assessment and other authorised work.

Read the canonical `ki-agent-coordination-paperclip` skill and its existing-estate onboarding guide. Draft a bootstrap/rebootstrap plan for the current Paperclip company. Resolve its organisation code and Agora from verified company context and returned repository evidence; make any missing or ambiguous binding the first decision rather than guessing. Reconcile existing projects, tasks, decisions, agent skill access, roadmap task links and recurring obligations without duplicates. Reconcile the agreed recurring checklist, repository definitions appropriate to each repository's type and needs, and existing Paperclip routines; use the verified Agora home as the default owner of shared definitions and reports. Assess whether an authorised human or alternate agent can continue from repository-owned knowledge with its declared dependencies. Identify repository-project discovery tasks, including deterministic kind/shape resolution and verification of the declared skill baseline in each execution workspace. Do not create projects or tasks, hire agents, resume held work, change repositories, or activate schedules before approval. Daily preflight is audit plus conform dry-run only, feeding the 08:00 daily report in the company's configured timezone. Include the shared ad-hoc/weekly master review and unresolved schedule, timezone and budget decisions. Return the plan, exact proposed changes, unresolved decisions, and the smallest next approval. Lead reports and decision requests with a short, everyday-language account of what is known, what can continue, what must wait, and who needs to act; put technical evidence underneath.
