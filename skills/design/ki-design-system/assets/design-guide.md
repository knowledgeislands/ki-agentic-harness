# Design the <surface>'s pages

<Who this guide is for and what they will be able to do once they have read it: design or change a page so it looks and behaves like the rest. Name the token source by its path, and say that the token source, the checks and the tests win where they disagree with this guide.>

## Principles

<Three to six rules every page follows, each checkable or reviewable.>

## Colour

<Which tokens to use for chrome, for meaning and for selection. How a categorical palette assigns slots and codes. Name tokens; never repeat a value.>

## Type

<The scale by role, as a table: use, size token or step, weight, notes. Numeric styles for dates and counts.>

## Layout

<Page structure, content widths, breakpoints, spacing and grouping.>

## Components

<The reusable pieces, as a table: component, name or class, where it lives, when to use it.>

## Showing state

<Each state the interface shows, as a table: state, how it looks, its second, non-colour carrier.>

## Interaction and accessibility

<Keyboard, focus, roles, labels, touch targets and the accessibility scan.>

## Enhancement

<What is rendered without script, what script adds, and where readers' choices are kept.>

## Words

<The voice, the terms and how interface text is written.>

## Before you merge

<The commands that run the design checks, and the manual review steps: widths, themes and modes, without script, keyboard alone.>
