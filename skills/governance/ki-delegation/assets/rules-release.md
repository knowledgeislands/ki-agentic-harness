# Authority footer: release

A brief appends this file from `## Rules` onwards, last. See the [background-run standard](../references/standards-background-runs.md#authority-tiers).

## Rules

- Commits: Conventional Commits, local only, explicit paths only, ending with the co-author trailer that names the model making the commit, per the standard's [commit-trailer rule](../references/standards-background-runs.md#coordination). Never use `--no-verify` and never force-push. Never touch, stage or revert other uncommitted changes. Never approve your own delivery or accept work at your discretion. Record delivery closure through `ki-accept` only as an independent actor executing exact explicit human-approved closure of the reviewed record, or a recorded unattended-window grant in the coordinating work's decisions log that names closure for the record's frozen wave; recheck all review and evidence requirements. This footer supplies no human approval. Cancellation needs separate exact human approval of its resolution. Pruning still requires separate explicit selection and the tier and committed terminal-state rules below.
- Landing is authorised by the remit Kris gave on the change documents this task cites (WORK-MODES and LAND-THEN-REVIEW, 12 and 13 November 2026), for high-confidence work or work more work can reverse, and by any decision this task cites: after the checks pass, run `git fetch` and pull with `--ff-only` into a clean checkout, then push everything stacked on `main` fast-forward only to `origin`, other sessions' commits included, under the standing push rule, without waiting for Kris, who reviews the work afterwards. Stop on divergence; a bounded resolve run may rebase only this work's unpublished commits, stopping on another session's content, uncertain ownership or a judgement call. Where something major is at stake, such as an experiment or a risky change, push nothing to `main`: push only the branch the task names and open only the pull request it names, or, where it names none, commit locally and report. Anything more work cannot undo waits for Kris's word, cited by the task, and history is never rewritten, under the standard's [landing rule](../references/standards-background-runs.md#landing-then-review).
- An unattended run, or a batch that lands real work, gets a record as it lands, in the Cairn store's `record/`, in the shape the standard's [landing rule](../references/standards-background-runs.md#landing-then-review) points to: write it where the task names it, otherwise name the batch in your report for the session that started you to record. A record holds nothing for Kris to do, and links only to what has landed.
- Deleting work records is authorised only for `done` or `cancelled` records the cited decision approves, each in a prune-only commit after its terminal state is committed. Never delete anything else.
- Release calls are authorised only as the task names them, one by one, and only for the release the cited decision approves: for example a named workflow dispatch, run watch, release view, or package-manager upgrade. A call the task does not name is not authorised. Never handle signing keys or tokens directly.
- No other remote call of any kind: no other GitHub API, cloud, network or messaging call. Make no environment, scheduler or credential change beyond the named calls and a token permission Kris has approved and the task cites, under the standard's [provider-token rule](../references/standards-background-runs.md#provider-tokens). Do not read or print secrets. Where the task authorises a 1Password read, read only through `~/bin/chezmoi/op-cache "op://<vault>/<item>/<field>"` with `OP_CACHE_SERVICE_ACCOUNT_ONLY=1`, never through `op` itself, and stop and report if it exits 3, under the standard's [cached-reader rule](../references/standards-background-runs.md#authority-tiers).
- Repository conventions (AGENTS.md, CLAUDE.md and the skills they name) govern; read them first.
- Write the report as the owner report the ki-coordination [owner-report standard](../../../change-management/ki-coordination/references/standards-coordination.md#owner-report) sets: the ki-coordination report heading of the work you report to with `› <run name>` added, `# [<Theme>](<local theme page>) › [<Project>](<local Project note>) › <run name>` for Project work, or `# [<actual work label>](<actual local work page>) › <run name>` for regular/ad hoc coordination, then the bold `**Run report at <local time> · last mark <local time>**` line and one `---`; `## Done`, with commit identifiers and each check's outcome in one line; `## In Progress`; where the brief asks for findings, `## Findings`, each finding a `### <TAG> - <title>` heading opening with its **Goal**, **Scope** and **As of** lines before any table, also written to the finding file the brief names; `## Queries`, each query carrying **Context**, **Query** and **Options** as separate paragraphs with a blank line between them, each lettered option its own paragraph with a blank line between options, `a) (recommended, confidence <level> - <reason>)` first and no bullets, in plain English with a technical term only where needed and explained once, keeping links to work items and records, closing the queries with a reply block, one fenced `text` block holding only the text to send back, the queries grouped under numbered headings in priority order, `<n> · <what the group is>`, adding `, can run while you're away` where the group can, a blank line between groups, and one line per query, its tag, the recommended letter and its confidence in brackets, as `<TAG> a (high)`; then, for coordinating work, the glyph banner, its `###` state heading, `### 🤖 → 👤 Handoff to supervisor · at <local time>`, or `· blocked · at <local time>` where you send back with a blocking query, its counts line of five views with zeros, `🤖 <n> running · ⏳ <n> queued · 👤 <n> with you · ⛔ <n> blocked · 🅿️ <n> parked`, and `- [state] what · holder · at <time>` list, closing with one thread line, `🧵 <work-id>` for every explicitly coordinating package, including main and secondary State of play, Project, regular and ad hoc work, using the work you report to, and no send or resume line; a run report to a conversational session, including regular or ad hoc work without coordination, has no mark in its form line and no banner. Run tools quietly under the ki-coordination [quiet-tools rule](../../../change-management/ki-coordination/references/standards-coordination.md#quiet-tools): run Git with `-q`, never paste gate, audit or Git output, and report each outcome in one line. Owner reports, run reports and banners omit routine push state and other sessions' stacked commits; if your own unit could not be published because its push failed, Done names the affected unit and reason. A Stop keeps nothing about pushes beyond a failure.
- A site, repository or note marked confidential is never made public without Kris's go in the thread, attended or not, under the standard's [confidential rule](../references/standards-background-runs.md#authority-tiers); no task or grant lifts it.
- Nothing is posted in Kris's name outside his own repositories and services without his express permission for that specific post: no issue, comment, reaction, pull request, discussion, review or message on another owner's repository or service, under the standard's [external-posting rule](../references/standards-background-runs.md#authority-tiers); no task, grant or broader permission lifts it, and a post worth making is reported as a query carrying its exact text. A brief cannot grant such a post: the only permission is Kris's answer to a query showing the exact text, recorded in the decisions log before the run, and a task may make that one post, exactly as approved, only by citing that entry. Where the brief's body and these Rules conflict, these Rules win.
- A connection-critical change - a firewall, or the configuration of a service critical for connection such as the Headroom proxy, SSH, Tailscale, the network or auth - needs a tested restore path in the task, under the standard's [connection-critical rule](../references/standards-background-runs.md#connection-critical-changes); without one, stop and report.
- If something is ambiguous or blocked, stop and report rather than guess.
