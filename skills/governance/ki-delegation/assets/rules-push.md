# Authority footer: push

`ki agent launch --rules push` appends this file from `## Rules` onwards. See the [background-run standard](../references/standards-background-runs.md#authority-tiers).

## Rules

- Commits: Conventional Commits, local only, explicit paths only, ending with the co-author trailer that names the model making the commit, per the standard's [commit-trailer rule](../references/standards-background-runs.md#coordination). Never use `--no-verify` and never force-push. Never touch, stage or revert other uncommitted changes. Never accept, prune or delete work records.
- Pushing is authorised by the decision this task cites: after the checks pass, run `git fetch` and pull with `--ff-only` into a clean checkout, then push everything stacked on `main` fast-forward only to `origin`, other sessions' commits included, under the standing push rule. Stop on divergence; a bounded resolve run may rebase only this work's unpublished commits, stopping on another session's content, uncertain ownership or a judgement call.
- No other remote call of any kind: no GitHub API, cloud, network or messaging call. Make no environment, scheduler or credential change. Do not read or print secrets.
- Repository conventions (AGENTS.md, CLAUDE.md and the skills they name) govern; read them first.
- Write the report as the owner report the ki-coordination [owner-report standard](../../../change-management/ki-coordination/references/standards-coordination.md#owner-report) sets: the ki-coordination report heading of the work you report to with `› <run name>` added, `# [<Theme>](<local theme page>) › [<Project>](<local Project note>) › <run name>`, then the bold `**🤖 → 👤 Handoff to supervisor · Run report at <local time> · last mark <local time>**` line, with `· blocked` after the state where you send back with a blocking query, and one `---`; `## Done`, with commit identifiers and each check's outcome in one line; `## In Progress`; where the brief asks for findings, `## Findings`, each finding a `### <TAG> - <title>` heading opening with its **Goal**, **Scope** and **As of** lines before any table, also written to the finding file the brief names; `## Queries`, each query carrying **Context**, **Query** and **Options** with `a) (recommended, confidence <level> - <reason>)` first and no bullets, and no reply block, the owner answering in speech; then, for coordinating work, the glyph banner, its `###` state heading, counts line and `- [state] what · holder · since` list, closing with one thread line, `🧵 Coordination thread · <label> (<id>)` for Project work or `🧵 State of play thread · <label> (<id>)` for territory work, using the work you report to, and no send or resume line; a run report to a conversational session or ad hoc work has no mark in its form line and no banner. Run tools quietly under the ki-coordination [quiet-tools rule](../../../change-management/ki-coordination/references/standards-coordination.md#quiet-tools): run Git with `-q`, never paste gate, audit or Git output, and report each outcome in one line. Owner reports, run reports and banners omit routine push state and other sessions' stacked commits; if your own unit could not be published because its push failed, Done names the affected unit and reason. A hold report keeps nothing about pushes beyond a failure.
- A connection-critical change - a firewall, or the configuration of a service critical for connection such as the Headroom proxy, SSH, Tailscale, the network or auth - needs a tested restore path in the task, under the standard's [connection-critical rule](../references/standards-background-runs.md#connection-critical-changes); without one, stop and report.
- If something is ambiguous or blocked, stop and report rather than guess.
