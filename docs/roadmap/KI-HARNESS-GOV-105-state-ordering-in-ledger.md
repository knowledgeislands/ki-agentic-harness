# KI-HARNESS-GOV-105: State ordering in ledger

## Goal

Someone about to allocate a roadmap number learns the order of steps from the ledger they are already opening, rather than from a standard they may not think to consult. The ledger says what it is for and what to do with it, in every repository that has one.

## Context

`docs/roadmap/_ISSUES.md` carries instructions today: "Allocate the next work item in its area as one greater than that area's high-water mark; never lower a value or reuse an issued number after a record is pruned." Those instructions are incomplete now that `KI-HARNESS-GOV-104` has landed (accepted in `22029fde`, since pruned), because the load-bearing part of the rule is an ordering - commit the advance, then write the record - and the file that is the reservation says nothing about it.

The body text cannot simply be edited. It is generated by `issueLedger()` in `skills/change-management/ki-work-roadmap/scripts/rubric/contexts/roadmap-evidence.ts`, and `ledgerAllocation()` in the same module accepts a ledger only when the file is byte-identical to that output. A ledger that differs by one sentence is not a ledger with extra prose; it fails `ROAD-7` as "must use the canonical immutable ledger shape". Byte-exactness is deliberate - it is what stops a ledger from drifting into an editable narrative - so the fix is a generator change, not a file change.

A generator change is a fleet event. Every repository whose ledger currently conforms would begin failing `ROAD-7` the moment the expected text changed, and `CONFORM` cannot repair it: `ki-work-roadmap` scaffolds a ledger only when it is absent and never overwrites one, precisely so it cannot destroy a hand-corrected allocation. There are 25 repositories registered in the estate, so an unstaged change converts one sentence of guidance into 25 audit failures with no automated repair path.

## Boundary

In scope: the generated ledger body text in both issuing modes; a bounded, non-destructive `CONFORM` repair for a ledger whose frontmatter allocation is valid and whose body is a recognised superseded canonical form; the order of the two changes; and the fixture and test updates they require.

Out of scope: the ordering rule itself and its home in the standards, delivered by `KI-HARNESS-GOV-104`; the frontmatter allocation shape, which does not change; any relaxation of byte-exact body validation into fuzzy matching; running `CONFORM` in other repositories, which each repository does under its own authority after it next updates its harness; and the `Streams/Roadmap/_ISSUES.md` equivalent beyond keeping the two issuing modes consistent.

## Discussion

### Why a repair path comes first

The obvious sequence - change the generator, then fix 25 ledgers - makes every repository fail its roadmap audit for as long as the migration takes, and a repository that is not visited stays failing indefinitely. The safer sequence is to teach `CONFORM` to recognise the previous canonical body as a repairable state first, so that changing the generator produces a fixable finding rather than a manual chore. That keeps `CONFORM`'s existing refusal to overwrite a ledger it does not recognise, which is the property worth protecting.

Recognising an earlier canonical form means keeping a short list of superseded body texts rather than accepting arbitrary prose. That is a real maintenance cost and should be stated as one, not hidden: the alternative is that the ledger body can never change again.

### Alternative: leave the ledger silent

The ledger could simply keep its current text and let the standards own the ordering. This is not obviously wrong - the standards are the contract, the rubric cites them, and a writer following `ki-next` never reads the ledger body for instructions. The cost is that the file which is the reservation gives a wrong impression of what taking a number involves, and the one instruction it does give describes the read and not the commit. If the repair path proves more expensive than the guidance is worth, closing this record as a considered `rejected` disposition is a legitimate outcome.
